# Нефункциональные требования

Версия 0.3. Банк вымышленный, объёмы — допущение. Для каждого требования указано, что именно измеряем и где.

| ID | Требование | Как измеряем |
|---|---|---|
| NFR-01 | `POST /v1/transfers` отвечает не дольше 500 мс для 95% и 1 с для 99% запросов при 50 переводах в секунду | На API-шлюзе, в каждом 5-минутном окне часа пик: ночные часы не размывают пиковую нагрузку. Антифрод и проводка в это время не входят (ADR-001) |
| NFR-02 | От нажатия «Перевести» до финального статуса на экране — не дольше 3 с для 95% переводов без ожидания человека. Переводы, попавшие на проверку из-за таймаута антифрода, остаются в выборке | Клиентская телеметрия приложения: от нажатия до показа финального статуса, в часы пик. Серверная сверка: от входа запроса на шлюз до `occurredAt` финального события, p95 не больше 2,5 с. Бюджет-допущение: синхронная часть до 0,5 с (NFR-01), антифрод до 1 с, проводка до 0,3 с, доставка статуса клиенту до 1 с |
| NFR-03 | Доступность создания перевода — 99,9% в месяц | Доля ответов не 5xx на шлюзе. 503 с Retry-After считается неуспехом |
| NFR-04 | Переводы и проводки не теряются при отказе базы: RPO = 0. Восстановление — не дольше 15 мин | Синхронная реплика; учения с переключением раз в квартал |
| NFR-05 | Отправитель определяется по токену приложения (OAuth 2.0), а не по телу запроса. Межсервисные вызовы — по mTLS, колбэк антифрода — только с сертификатом из доверенного списка | Автотесты: чужой счёт списания → 403, чужой перевод → 404, колбэк без сертификата → отказ соединения |
| NFR-06 | Номер телефона не попадает в URL и логи, в логах он маскируется: `+7 *** ***-45-67`. В событиях — только идентификаторы клиентов. Имя получателя сокращено | Автотест на маскирование; ревью логов тестового стенда |
| NFR-07 | `traceparent` проходит от шлюза через все вызовы, outbox и события. В логах — `transferId` и `traceId` | Тест: по `traceId` из ответа находится вся цепочка вызовов |
| NFR-08 | Алерты: задача продолжения не выполнена дольше P-12; перевод без открытой задачи; лаг outbox больше 30 с; любое событие в DLQ; доля переводов на проверке из-за таймаута антифрода больше 5% за 5 мин; расхождение сверки; к 18:00 рабочего дня Банка России не загружен курс, вступающий в силу на следующий день | Каждый алерт проверяется на тестовом стенде искусственным сбоем. Что делать по каждому — [runbook](../operations/runbook.md) |
| NFR-09 | Переводы, проводки и решения антифрода хранятся не меньше 5 лет — требование 115-ФЗ, порядок отсчёта согласуется с комплаенсом. Токены получателей удаляются через сутки после истечения, события в Kafka живут 14 дней | Регламентные задания и настройки топика |
| NFR-10 | Нагрузка: в среднем 8 переводов в секунду, около 20 млн в месяц; пик — 50 в секунду, в 6 раз выше среднего: вечер пятницы, праздники, дни зарплаты. Рост в 3 раза — без смены архитектуры | Нагрузочный тест: 150 переводов в секунду 30 мин, NFR-01 выполняется. Параллельные операции леджера — [`ledger-concurrency-check.sh`](../design/ledger-concurrency-check.sh) |
| NFR-11 | Совместимость. Версия API — в пути, `/v1`. Новые поля добавляются без смены версии, клиенты игнорируют незнакомые поля. Несовместимое изменение — `/v2`, `/v1` поддерживается не меньше 6 мес. У событий — `schemaVersion`, в версии 1 только совместимые изменения | Ревью контракта при каждом изменении; линтер в CI |
| NFR-12 | Сутки и месяц для лимитов — по Москве. Время в API — ISO 8601 со смещением | Тест на переводы в 23:59 и 00:01, в последний день месяца |
