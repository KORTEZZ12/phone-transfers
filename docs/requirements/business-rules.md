# Бизнес-правила

Версия 0.2. Банк вымышленный, поэтому источник почти всех правил — **решение** из [журнала решений](../decisions/decision-log.md). Числа вынесены в [параметры](#параметры).

## Получатель

| ID | Правило |
|---|---|
| TR-01 | Получатель ищется по номеру телефона в формате +7XXXXXXXXXX среди клиентов банка. Отправитель видит имя и первую букву фамилии: «Иван П.» |
| TR-02 | Поиск возвращает токен получателя, он действует P-01 (10 мин). Перевод создаётся по токену, а не по номеру: если за это время номер перешёл к другому клиенту, деньги уйдут тому, кого отправитель видел на экране (D-05). Токен привязан к отправителю, который искал: чужой токен отклоняется |
| TR-03 | Поиск ограничен: не больше P-02 (10) запросов в минуту и P-03 (50) в сутки на отправителя. При превышении отправитель видит, через сколько можно повторить |
| TR-04 | Перевести самому себе по своему номеру нельзя: для этого есть перевод между своими счетами |
| TR-05 | Деньги зачисляются на основной счёт получателя в валюте перевода. Если такого счёта нет, отправитель узнаёт об этом при поиске, до подтверждения |

## Сумма и лимиты

| ID | Правило |
|---|---|
| TR-06 | Сумма — от 1 единицы валюты до лимита на операцию, не больше двух знаков после запятой |
| TR-07 | Лимиты отправителя в рублях: на операцию — P-04, в календарные сутки по Москве — P-05, в календарный месяц — P-06 |
| TR-08 | В лимит входят выполненные переводы и переводы в обработке или на проверке. Проверка лимита и его резерв — одна атомарная операция: два параллельных перевода вместе лимит не превысят (D-04) |
| TR-09 | Сумма отклонённых, отменённых и не выполненных переводов возвращается в доступный лимит |

## Создание перевода и повторы

| ID | Правило |
|---|---|
| TR-10 | Каждый запрос на создание перевода содержит ключ идемпотентности. Приложение создаёт его один раз на экране подтверждения и повторяет с ним запрос при любой сетевой ошибке (D-08) |
| TR-11 | Повтор с тем же ключом и теми же данными в течение P-07 (24 ч) возвращает тот же перевод с актуальным статусом. Тот же ключ с другими данными — отказ «Ключ уже использован для другого перевода». Повтор позже P-07 — отказ «Создайте перевод заново», нового перевода не создаётся. Ключ уникален в пределах отправителя всегда |
| TR-12 | При создании перевода сумма блокируется на счёте отправителя (холд). Если доступного остатка не хватает, перевод сразу отклоняется и деньги не блокируются |
| TR-13 | Создание перевода синхронное до блокировки средств: отправитель сразу узнаёт, принят перевод или отклонён по лимиту или остатку. Проверка антифродом и проводка идут асинхронно, итог отправитель видит в статусе и пуше (D-02) |

## Холд и проводки

| ID | Правило |
|---|---|
| TR-14 | Списание и зачисление — одна транзакция леджера: дебет счёта отправителя и кредит счёта получателя на одну сумму. Частичного выполнения не бывает |
| TR-15 | Проводки не меняются и не удаляются. Ошибку исправляют обратной проводкой (сторно) со ссылкой на исходную (D-06) |
| TR-16 | Каждая операция леджера (холд, снятие холда, проводка) идемпотентна по идентификатору перевода: повтор не создаёт второй операции, а возвращает результат первой |
| TR-17 | Холд снимается при отклонении, отмене и техническом сбое перевода. Регламентная проверка раз в P-08 (15 мин) снимает холды без активного перевода и заводит инцидент |
| TR-18 | Если к моменту проводки счёт получателя закрыт или заблокирован, перевод отклоняется, холд снимается |

## Антифрод и ручная проверка

| ID | Правило |
|---|---|
| TR-19 | Каждый перевод проверяет антифрод. Решения: разрешить, отклонить, отправить на ручную проверку |
| TR-20 | Если антифрод не ответил за P-09 (2 с), перевод уходит на проверку, а проверка автоматически повторяется каждые P-10 (5 мин). Без решения антифрода перевод не выполняется (D-03) |
| TR-21 | Ручная проверка длится не дольше P-11 (48 ч). Нет решения к сроку — перевод отклоняется, холд снимается. Срок — параметр, согласуется с комплаенсом |
| TR-22 | Пока перевод на проверке, отправитель видит статус «На проверке» и может отменить перевод. Выполненный или отклонённый перевод отменить нельзя |
| TR-23 | Если решение антифрода и отмена отправителем пришли одновременно, применяется то, что зафиксировано первым. Второе действие получает отказ с актуальным статусом перевода |

## Валюта

| ID | Правило |
|---|---|
| TR-24 | Переводы в долларах, евро и юанях — только между счетами в одной валюте, без конвертации (D-09) |
| TR-25 | Лимиты для валютных переводов считаются в рублёвом эквиваленте по официальному курсу ЦБ на дату операции |
| TR-26 | Курсы ЦБ загружаются из SOAP-сервиса DailyInfo раз в день и хранятся с датой. Если загрузка не удалась, используется последний загруженный курс, операционный отдел получает алерт |

## События, уведомления, сверка

| ID | Правило |
|---|---|
| TR-27 | Перевод, принятый к исполнению, публикует событие при блокировке средств и при каждой смене статуса, который видит клиент. Событие записывается в той же транзакции, что и статус, и не теряется при сбое (D-07). Отказ при создании событий не порождает: клиент получил его в ответе на запрос |
| TR-28 | О результате перевода отправитель и получатель получают пуш. Уведомление — следствие события: его потеря или задержка на сам перевод не влияет |
| TR-29 | Потребители событий обрабатывают повтор без побочных эффектов (по идентификатору события) и не откатывают финальный статус событием, пришедшим позже не по порядку |
| TR-30 | Перевод в промежуточном статусе (кроме «На проверке») дольше P-12 (5 мин) доводится автоматически: повтор операции леджера с тем же идентификатором или отклонение со снятием холда, если леджер подтвердил, что операции не было. Операционный отдел получает алерт |
| TR-31 | Ежедневная сверка: у каждого выполненного перевода ровно одна пара проводок, сумма проводок по переводам за день совпадает с суммой выполненных переводов. Расхождение — инцидент операционному отделу |
| TR-32 | Комментарий к переводу — до P-13 (140) символов, его видит получатель |
| TR-33 | Комиссии нет (D-10) |
