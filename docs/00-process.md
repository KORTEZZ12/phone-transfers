# Как устроена работа над проектом

Проект учебный, команда — симуляция: я системный аналитик, остальные роли выполняют ИИ-агенты. Банк и продукт вымышленные, правила продукта — мои решения.

| Роль | Кто | Что делает |
|---|---|---|
| Системный аналитик | я | Правила продукта, решения, ревью черновиков, приёмка |
| Аналитик-помощник | ИИ (Claude) | Черновики артефактов по моим вводным |
| Заказчик | ИИ-агент с персоной владельца продукта переводов | Приоритеты, изменения по ходу проекта |
| Ревьюер требований | ИИ, скиллы `/sar` и `/sar-crosscheck` в отдельном чате | Независимое ревью требований, контрактов и sequence |
| Архитектор | ИИ-агент | Ревью ADR и НФТ |
| Разработчик | ИИ-агент (Claude Code) | Mock-сервер и проверки по контракту, вопросы аналитику в issues |
| QA | ИИ-агент | Тесты по таблице отказов |

Решения принимаю я. Черновик становится частью проекта после моего ревью, правки видны в истории PR.

Как идёт работа с замечаниями: находка ревью → issue по шаблону → PR, который её закрывает, → зелёный CI → слияние. Прямых коммитов в `main` нет. Отчёты ревью — в [docs/reviews](reviews/README.md).

## Итерации

| № | Что | Статус |
|---|---|---|
| 1 | Рамки, бизнес-правила, статусная модель, таблица отказов, решения | готово |
| 2 | НФТ, контракты OpenAPI и AsyncAPI, sequence по таблице отказов, модель данных и леджер, интеграция с ЦБ по SOAP, ADR | готово, 0.2 |
| 3 | Mock-сервер, Postman-коллекция с тестами, SQL сверки и витрина для отчётности | следующая |
| 4 | Независимое ревью `/sar` и `/sar-crosscheck`, исправления, ретро | готово, 0.3 |

Итерация 4 сделана раньше третьей: тесты по контракту, который потом поменяется, пришлось бы переписывать.

## Ретро итерации 4

| Что пошло не так | Что поменял в работе |
|---|---|
| Взаимоблокировку в леджере я «проверил» рассуждением, нашёл её нагрузочный тест | Каждое обещание про конкурентность подтверждается тестом в CI |
| Окно ключа идемпотентности в 24 ч перенёс из публичных API без контекста, и повтор после суток вёл к двойному переводу | Для каждого параметра отвечаю на вопрос: что видит клиент на границе значения |
| Требования 161-ФЗ записал «параметрами», хотя порядок параметром не сделать | Регуляторное требование — отдельные правила, статусы и процесс, а не строчка в ограничениях |
| Процесс обещал PR, а коммиты шли прямо в `main` | Только PR, CI обязателен |
| Шаги «сразу после коммита» терялись при падении | Каждый асинхронный шаг — задача в той же транзакции, что и статус |
