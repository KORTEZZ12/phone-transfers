Переводы по номеру телефона (1.0.0)

Download OpenAPI specification:

License: CC BY 4.0

API мобильного приложения для переводов между клиентами банка по номеру телефона и внутренний колбэк антифрода. Соглашения — в README: аутентификация, ключ идемпотентности, формат сумм, каталог ошибок.

Отправитель всегда определяется по токену доступа, а не по телу запроса. Банк вымышленный, домен bank.example зарезервирован для примеров.

Получатели

Поиск клиента банка по номеру телефона

Найти получателя по номеру телефона

POST, а не GET: номер телефона не должен попадать в URL и журналы доступа (TR-01). Возвращает токен получателя: перевод создаётся по нему, а не по номеру (TR-02). Частота ограничена: P-02 в минуту и P-03 в сутки на отправителя (TR-03).

Переводы

Создание, статус и отмена перевода

Создать перевод

Синхронно: проверка лимита, его резерв и блокировка суммы на счёте (TR-08, TR-12, TR-13). Дальше асинхронно: антифрод и проводка. Итог — в GET /v1/transfers/{transferId} и пуше.

Повтор с тем же Idempotency-Key и тем же телом в течение P-07 возвращает тот же перевод с актуальным статусом и заголовком Idempotent-Replayed: true. Если исходный запрос был отклонён, повтор возвращает тот же отказ (TR-11).

Отменить перевод на проверке

Отменить можно только перевод в статусе ON_REVIEW (TR-22). Повторная отмена отменённого перевода возвращает 200 и тот же перевод, поэтому ключ идемпотентности не нужен. Если одновременно пришло решение антифрода, применяется то, что зафиксировано первым (TR-23).

Внутренние

Вызовы от систем банка, не из приложения

Решение антифрода по ручной проверке

Вызывает антифрод, когда сотрудник принял решение. Идемпотентно по decisionId. Если перевод уже в финальном статусе (отменён отправителем или истёк срок проверки), ответ — 200 с applied: false и текущим статусом: антифроду нечего исправлять, ему нужно только закрыть кейс. Ошибка 4xx тут бесполезна, на неё нельзя отреагировать.
