# Соглашения API

Версия 0.2. Контракты: [`openapi.yaml`](openapi.yaml) — API для приложения и колбэк антифрода, [`asyncapi.yaml`](asyncapi.yaml) — события в Kafka.

## Проверка контрактов

```bash
npx @redocly/cli lint openapi.yaml                 # схема, ссылки, соответствие примеров схемам
npx @redocly/cli build-docs openapi.yaml           # HTML-документация для GitHub Pages
npx @stoplight/prism-cli mock openapi.yaml         # mock-сервер по примерам из контракта
```

AsyncAPI проверяется официальным парсером `@asyncapi/parser`: спецификация 3.1.0, без ошибок и предупреждений.

## Аутентификация

Приложение передаёт `Authorization: Bearer <JWT>`. Отправитель всегда берётся из токена: идентификатор клиента в теле запроса не принимается, иначе можно подставить чужой.

## Идемпотентность

- `Idempotency-Key` обязателен для `POST /v1/transfers`. Приложение создаёт UUID один раз на экране подтверждения и хранит его вместе с телом запроса, пока не получит перевод в ответе.
- Ключ проверяется первым, до токена получателя, счёта, лимита и остатка. Поэтому повтор уже созданного перевода не получит `RECIPIENT_TOKEN_EXPIRED` или `LIMIT_EXCEEDED`, даже если с тех пор истёк токен или изменился лимит.
- Повтор с тем же ключом и тем же телом в любое время возвращает 200, заголовок `Idempotent-Replayed: true` и перевод с актуальным статусом. Ключ хранится вместе с переводом, срока у повтора нет. Если исходный запрос был отклонён, повтор возвращает тот же отказ.
- Пока первый запрос с этим ключом выполняется (аренда P-14), повтор получает 409 и `Retry-After: 1`. После окончания аренды повтор продолжает обработку с того места, где остановился первый запрос.
- Тот же ключ с другим телом — 422 `IDEMPOTENCY_KEY_REUSED` с `existingTransferId`. Это всегда дефект приложения: оно показывает существующий перевод, отправляет событие в мониторинг и само ничего не переотправляет. Новый перевод — только через новое подтверждение и новый ключ.
- Тело сравнивается после нормализации: `recipientToken` и `sourceAccountId` в нижнем регистре, `amount.value` с двумя знаками после точки, `amount.currency` как есть, `comment` без пробелов по краям; `null`, пустая строка и отсутствие `comment` равны.
- Повторы приложения: при сетевой ошибке, таймауте P-15 и 503 — до P-16 раз с паузой 1, 2 и 4 с ± 50%, на 409 — через `Retry-After`. Потом экран «Статус уточняется» и повтор того же запроса при следующем открытии приложения ([состояния экрана](../design/client-states.md)).
- Отмена перевода идемпотентна сама по себе: повторная отмена возвращает тот же отменённый перевод.

## Форматы

- Сумма — объект `{value, currency}`, `value` — строка с точкой и не больше чем двумя знаками: числа с плавающей точкой теряют копейки. Валюта — ISO 4217.
- Телефон — E.164: `+79991234567`. Передаётся только в теле запроса.
- Время — ISO 8601 со смещением.
- Трассировка — W3C `traceparent`. В каждой ошибке есть `traceId` для обращения в поддержку.

## Каталог ошибок

Ошибки в формате RFC 9457 (`application/problem+json`) с машиночитаемым полем `code`. Приложение решает, что делать, по `code`, а текст `title` можно показать как есть. У каждого кода есть действие для приложения: ошибка, на которую нельзя отреагировать, контракту не нужна.

| code | HTTP | Когда | Что делает приложение |
|---|---|---|---|
| VALIDATION_ERROR | 400 | Неверный формат поля | Подсвечивает поле из `errors` |
| IDEMPOTENCY_KEY_REQUIRED | 400 | Нет заголовка | Дефект приложения: в лог и мониторинг |
| UNAUTHORIZED | 401 | Токен истёк | Обновляет токен и повторяет с тем же ключом |
| ACCOUNT_NOT_OWNED | 403 | Счёт списания не принадлежит отправителю | Просит выбрать другой счёт |
| RECIPIENT_NOT_FOUND | 404 | Нет клиента банка с этим номером | «Проверьте номер» |
| TRANSFER_NOT_FOUND | 404 | Нет такого перевода или он чужой | Обновляет список переводов |
| IDEMPOTENCY_KEY_IN_PROGRESS | 409 | Первый запрос с этим ключом ещё идёт | Повторяет через `Retry-After` с тем же ключом, суммарно не дольше P-14, затем «Статус уточняется» |
| TRANSFER_NOT_CANCELLABLE | 409 | Перевод уже не на проверке | Показывает `currentStatus` |
| SELF_TRANSFER | 422 | Свой номер | Предлагает перевод между своими счетами |
| RECIPIENT_TOKEN_EXPIRED | 422 | С поиска прошло больше 10 мин, перевода с этим ключом нет | Повторяет поиск, после нового подтверждения создаёт новый ключ |
| RECIPIENT_CURRENCY_UNAVAILABLE | 422 | У получателя нет счёта в этой валюте | Предлагает валюту из `currencies` поиска |
| LIMIT_EXCEEDED | 422 | Лимит на операцию, сутки или месяц | Показывает доступную сумму из `limit` |
| INSUFFICIENT_FUNDS | 422 | Не хватает денег | Предлагает другой счёт |
| SOURCE_ACCOUNT_UNAVAILABLE | 422 | Счёт списания заблокирован или закрыт | Предлагает другой счёт |
| IDEMPOTENCY_KEY_REUSED | 422 | Тот же ключ, другие данные | Показывает перевод `existingTransferId`, пишет дефект в мониторинг, сам не переотправляет |
| LOOKUP_RATE_LIMITED | 429 | Слишком много поисков | Показывает таймер по `Retry-After` |
| SERVICE_UNAVAILABLE | 503 | Зависимая система недоступна | Повторяет через `Retry-After` с тем же ключом |

Асинхронные отказы приходят не ошибкой, а статусом REJECTED с `rejectReason`: FRAUD_SUSPECTED, REVIEW_EXPIRED, RECIPIENT_ACCOUNT_UNAVAILABLE.

## Версии

Версия — в пути, `/v1`. Совместимые изменения (новые необязательные поля, новые значения в описаниях) выходят без смены версии, клиенты игнорируют незнакомые поля. Несовместимые — `/v2`, `/v1` поддерживается не меньше 6 мес ([NFR-11](../requirements/nfr.md)).
