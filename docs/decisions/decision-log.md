# Журнал решений

Продуктовые и ключевые архитектурные решения. Статусы: **предложено** — ждёт подтверждения, **принято**, **отклонено**. Все решения итерации 1 приняты. Подробный разбор вариантов — в ADR: [ADR-001](adr/ADR-001-sync-until-hold.md) для D-02, [ADR-002](adr/ADR-002-antifraud-fail-closed.md) для D-03, [ADR-004](adr/ADR-004-limit-reservation.md) для D-04, [ADR-003](adr/ADR-003-outbox.md) для D-07.

| ID | Решение | Почему | Альтернативы | Статус |
|---|---|---|---|---|
| D-01 | Только переводы внутри банка. СБП и другие банки вне рамок, точка расширения — транзитный счёт | Внутренний перевод показывает все механики надёжности без внешнего контура НСПК | Сразу проектировать СБП | принято |
| D-02 | Создание перевода синхронное до блокировки средств, дальше асинхронное: ответ сразу со статусом «В обработке», итог — в статусе и пуше | Отказ по лимиту и остатку клиент видит сразу; медленный антифрод не держит запрос | Полностью синхронно: ждать антифрод и проводку в запросе. Полностью асинхронно: принять без холда | принято |
| D-03 | Если антифрод недоступен, перевод уходит на проверку и автоповтор (fail-closed) | Без проверки антифродом перевод не выполняется | Пропускать без проверки до порога суммы (fail-open) | принято |
| D-04 | В лимит входят незавершённые переводы, проверка и резерв лимита атомарны | Иначе лимит обходится параллельными запросами | Считать только выполненные | принято |
| D-05 | Перевод создаётся по токену получателя из поиска, а не по номеру | Деньги уходят тому, кого отправитель видел на экране, даже если номер переназначили | Перевод по номеру | принято |
| D-06 | Леджер на двойной записи, проводки неизменяемы, исправления — сторно | Баланс всегда воспроизводится из проводок, ошибки видны в истории | Баланс полем, которое обновляется | принято |
| D-07 | Статус и событие пишутся в одной транзакции (outbox), в Kafka события переносит отдельный процесс | Нельзя потерять событие и нельзя отправить событие о статусе, который не сохранился | Писать в базу и Kafka по отдельности (dual write); CDC из журнала базы | принято |
| D-08 | Ключ идемпотентности создаёт приложение на экране подтверждения. Ключ хранится вместе с переводом и уникален в пределах отправителя всегда, повтор распознаётся без срока | Только клиент знает, повтор это или новый перевод. Окно в 24 ч отвечало ошибкой на повтор уже выполненного перевода, и приложение создавало второй (ревью 0.2) | Ключ на сервере; окно повтора 24 ч (было до 0.3) | принято, пересмотрено в 0.3 |
| D-11 | Аренда обработки: перевод ведёт один участник не дольше P-14. Повтор в это время получает 409, после — продолжает обработку | В NEW повтор получал то 409, то «продолжить» без критерия выбора | Всегда 409 до регламентной проверки; всегда продолжать параллельно | принято |
| D-09 | Валютные переводы — только в одной валюте, без конвертации; лимиты по курсу ЦБ | Конвертация — отдельный продукт со своими курсами и рисками | Конвертация при переводе | принято |
| D-10 | Без комиссии | Комиссия не добавляет механик надёжности, только проводку | Комиссия сверх месячного порога | принято |
