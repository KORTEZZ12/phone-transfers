# ADR-006. Перевод с признаками мошенничества ждёт подтверждения клиента

Статус: принято, сроки — на согласование с комплаенсом. Связано с D-13, TR-35…TR-38.

## Контекст

В версии 0.2 подозрительный перевод уходил на ручную проверку сотрудником службы безопасности. Клиент мог только отменить перевод, а через 48 ч без решения перевод отклонялся. Статья 8 161-ФЗ в редакции 369-ФЗ, действующей с 25 июля 2024 года, устроена иначе. Банк до списания проверяет признаки перевода без добровольного согласия клиента. Перевод с такими признаками приостанавливается, клиента уведомляют, и он сам решает, подтверждать ли перевод. Если клиент подтвердил, а по базе данных Банка России пришли сведения о получателе, исполнение откладывается, но затем перевод исполняется. Фраза «сроки и порядок — параметры» этого не закрывала: порядку нужны статусы и метод API, параметром их не сделать.

## Варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| Оставить внутреннюю ручную проверку | Ничего не менять | Не соответствует закону: решает сотрудник, а не клиент; подтверждённый перевод отклоняется |
| Явно исключить 161-ФЗ из рамок проекта | Честно и дёшево | Банк с таким продуктом не выйдет в прод; главный сценарий мошенничества не описан |
| Отдельные статусы приостановки и отложенного исполнения, подтверждение клиентом в API | Повторяет порядок закона; ручная проверка СБ остаётся для внутренних правил банка | Два новых статуса, новый метод, новая ветка в каждом артефакте |

## Решение

Третий вариант. Новые статусы:
- SUSPENDED, для клиента AWAITING_CONFIRMATION — ждём подтверждения до срока P-20;
- COOLING, для клиента DELAYED — подтверждён, исполнение отложено на P-21.

Новый метод `POST /v1/transfers/{id}/confirm`, решение антифрода SUSPEND, повторная сверка с базой ЦБ после подтверждения, пуш с запросом подтверждения. Ручная проверка сотрудником остаётся: сотрудник тоже может прийти к решению SUSPEND. Процесс с участием людей — в [BPMN](../../design/bpmn/antifraud-161fz.svg).

## Последствия

- Отказ без подтверждения получает отдельную причину NOT_CONFIRMED, клиент понимает, почему перевод не прошёл.
- Пока перевод ждёт подтверждения или отложен, холд остаётся, отправитель может отменить перевод.
- Подтверждённый перевод второй раз не приостанавливается: это гарантирует ограничение в модели данных.
- Сверку с базой ЦБ делает антифрод (допущение A5). Если банк решит сверять сам, появится ещё одна интеграция, а статусы останутся теми же.
- Сроки P-20 и P-21 и состав признаков нужно согласовать с комплаенсом до реализации. Модель от их значений не зависит.
