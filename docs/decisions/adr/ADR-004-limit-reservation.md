# ADR-004. Атомарный резерв лимита блокировкой строк

Статус: принято. Связано с D-04, TR-08, TR-09.

## Контекст

В лимит входят и незавершённые переводы. Два параллельных запроса одного отправителя не должны вместе превысить лимит, иначе лимит обходится двумя быстрыми нажатиями.

## Варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| Сумма переводов за период без блокировки | Просто | Гонка: оба запроса видят свободный лимит |
| Счётчик в Redis | Быстро | Вне транзакции с переводом: при сбое счётчик и переводы расходятся |
| Уровень изоляции SERIALIZABLE | Корректно без явных блокировок | Ошибки сериализации, нужны повторы в коде |
| Строки-счётчики DAY и MONTH в той же базе с блокировкой | Атомарно вместе с созданием перевода | Параллельные переводы одного клиента выстраиваются в очередь |

## Решение

Таблица `limit_usage` со строками на сутки и месяц. Резерв блокирует обе строки всегда в одном порядке и проверяет `reserved + used + сумма`. Переход перевода в финальный статус в той же транзакции переводит резерв в использованное или освобождает его.

## Последствия

- Проверено двумя параллельными сессиями PostgreSQL ([`concurrency-check.sh`](../../design/concurrency-check.sh)).
- Очередь возникает только между переводами одного отправителя, а их единицы в минуту, поэтому на NFR-01 это не влияет.
- Период лимита фиксируется при создании перевода, чтобы резерв снимался с того же периода, в который был поставлен.
