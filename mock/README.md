# Mock-сервер

Mock сервиса переводов с состоянием. Он отвечает по [OpenAPI](../docs/api/openapi.yaml) и держит те же правила, что [модель данных](../docs/design/data-model.md): статусную модель, задачи продолжения, резерв лимита, идемпотентные операции леджера, аренду, outbox, матрицу пушей и регламентную проверку. Mock по примерам из контракта (Prism) отвечает одинаково на любой запрос, поэтому таблицу отказов на нём не проверить. Этот mock проверяет.

Node 22, без зависимостей.

```bash
node mock/server.mjs                                  # http://localhost:4010, задачи выполняются сами раз в 200 мс
MOCK_AUTO_TICK_MS=0 node mock/server.mjs              # без фонового исполнителя: время двигают тесты (так работает CI)
MOCK_PORT=4011 MOCK_START=2026-12-31T23:59:00+03:00 node mock/server.mjs
```

| Файл | Что внутри |
|---|---|
| [`server.mjs`](server.mjs) | HTTP: публичный API, колбэк антифрода, управляющий API `/__mock` |
| [`bank.mjs`](bank.mjs) | Сервис переводов, леджер, антифрод, outbox и потребители событий |
| [`fixtures.mjs`](fixtures.mjs) | Клиенты, счета, курсы ЦБ и параметры P-xx |

## Время

Время в mock виртуальное и начинается с полудня 16 ноября 2026 года по Москве. Оно идёт вместе с реальным, а `POST /__mock/clock/advance` сдвигает его вперёд. По пути выполняется всё, что наступило: задачи продолжения с их паузами P-17, повторы у потребителей событий, регламентная проверка раз в P-08, загрузка курсов в начале суток. Поэтому 48 часов ручной проверки или 2 дня отложенного исполнения проходят за миллисекунды. Разброс пауз берётся из генератора с постоянным зерном, и прогон воспроизводим.

## Управляющий API

В проде его нет. Он нужен тестам, чтобы вызвать сбой и заглянуть внутрь.

| Метод | Что делает |
|---|---|
| `POST /__mock/reset` | Всё в исходное состояние |
| `GET /__mock/clock`, `POST /__mock/clock/advance` `{seconds, minutes, hours, days}` | Текущее время, сдвиг вперёд |
| `GET`, `POST /__mock/faults` | Сбои, таблица ниже |
| `GET /__mock/transfers/{id}` | Перевод изнутри: внутренний статус, версия, холд, проводки, задачи, проверки антифрода, события, пуши |
| `DELETE /__mock/transfers/{id}/tasks` | Потерять открытые задачи перевода: дефект для регламентной проверки |
| `GET /__mock/accounts/{id}`, `POST /__mock/accounts/{id}/status` `{status}` | Баланс, холды и доступный остаток; заблокировать или закрыть счёт |
| `POST /__mock/phones` `{phone, clientId}` | Номер перешёл к другому клиенту |
| `POST /__mock/ledger/late-hold/{id}` | Холд дошёл до леджера позже, чем перевод закрыли |
| `POST /__mock/ledger/postings` `{debit, credit, amount}` | Проводка в обход перевода: дефект для сверки |
| `GET /__mock/events?transferId=` | Outbox: события и признак публикации |
| `POST /__mock/events/{eventId}/redeliver` `{poison, reorder}` | Доставить событие ещё раз: дубль, перестановка или битое событие |
| `GET /__mock/pushes?transferId=`, `GET /__mock/dlq` | Ушедшие пуши, DLQ потребителя уведомлений |
| `GET /__mock/alerts`, `GET /__mock/incidents` | Алерты NFR-08 и инциденты регламентной проверки |
| `GET /__mock/antifraud` | Предохранитель и счётчики вызовов антифрода |
| `POST /__mock/cbr/load` | Загрузить курсы ЦБ сейчас |
| `GET /__mock/reconciliation?day=` | Ежедневная сверка, та же логика, что в [`reconciliation.sql`](../docs/design/reconciliation.sql) |

Сбои в `POST /__mock/faults`:

| Поле | Значения | Что происходит |
|---|---|---|
| `antifraud` | `UP`, `DOWN` | Антифрод не отвечает за P-09 |
| `ledger` | `UP`, `DOWN`, `LOST_RESPONSE` | Леджер не отвечает или выполняет операцию, но ответ теряется |
| `relay` | `UP`, `DOWN` | Relay outbox не публикует события |
| `cbr` | `UP`, `DOWN` | DailyInfo недоступен |
| `pushRecipientFailures` | число | Сколько раз подряд упадёт пуш получателю |
| `ledgerLatencyMs` | мс | Задержка холда в запросе на создание: так два запроса оказываются внутри создания одновременно |
| `requests` | `[{operation, mode, count}]` | Сбой запроса: `UNAVAILABLE` — 503 до обработки; `LOST_RESPONSE` — перевод создан, клиент получил 503; `CRASH_BEFORE_HOLD` — сервис упал после записи перевода |

## Чем mock отличается от сервиса

- Сервис переводов, леджер, антифрод, outbox, потребители событий и регламентная проверка работают в одном процессе. Сетевые сбои между ними моделируют `faults`.
- Гонки решает однопоточность Node: всё, что между `await`, атомарно. Блокировки PostgreSQL проверяют [`concurrency-check.sh`](../docs/design/concurrency-check.sh) и [`ledger-concurrency-check.sh`](../docs/design/ledger-concurrency-check.sh), а mock проверяет поведение API при параллельных запросах ([`tests/concurrency-check.mjs`](../tests/concurrency-check.mjs)).
- Срок ручной проверки и срок подтверждения применяются и при обращении к переводу, а не только регламентной проверкой. Это требование, а не упрощение: [находка F-7](../docs/testing/README.md#находки).
- mTLS колбэка антифрода не моделируется.
- Статус перевода и внутренние представления не сохраняются между перезапусками.
